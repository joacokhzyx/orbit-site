## The contract, and the limits

Orbit publishes what it can't do, next to the pages that use each feature,
because finding that out at midnight is a bad way to learn a language. This
is the short list; [known limitations](/docs/reference/limitations/) is the
long one, with the workaround for each.

<CardGrid>
  <Card title="No multipart uploads">
    The file helper compiles and saves nothing. The file server tutorial
    uploads raw bodies and says so.
  </Card>
  <Card title="No database migrations">
    Tables are created on startup and never altered. Adding a field later
    leaves the existing table alone.
  </Card>
  <Card title="No p50 or p99">
    The runtime reports a mean in microseconds, not a distribution. What isn't
    measured isn't exposed.
  </Card>
  <Card title="One host per cluster">
    The cluster command starts copies on this machine. There is no shared
    state, no proxying, and no failover.
  </Card>
</CardGrid>

## If a number matters to you

The honest state is that the end-to-end performance figures sit inside the
run-to-run noise of a shared machine, so the home page publishes none. The
method is written down, and it forbids the two shortcuts that make benchmark
documents worthless: converting CPU time into joules with a universal factor,
and reporting only the runs that worked.
